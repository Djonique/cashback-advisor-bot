# 💳 Cashback Advisor Bot

Telegram-бот на Java (Spring Boot), который помогает пользователям выбирать выгодную банковскую карту для оплаты на основе MCC-кода, категории кэшбэка или названия магазина.

🔗 **Ссылка на бота в Telegram:** [Кешбэк Помощник](https://t.me/CashbackAdvBot)

## 📖 О проекте

Пользователи часто теряются, пытаясь вспомнить, на какую карту настроен кешбэк в текущем месяце. Бот решает эту проблему:
1. Вы настраиваете категории и проценты кешбэка для своих банков один раз на текущий месяц.
2. При покупке вводите боту название магазина (например, «Пятёрочка»), категорию («Супермаркеты») или 4-значный MCC-код.
3. Бот мгновенно выдает список карт, отсортированный по размеру кэшбэка.

> ⚠️ **Дисклеймер:** Бот носит рекомендательный характер. Итоговый MCC-код зависит от терминала конкретного магазина. Бот не хранит данные ваших карт и не имеет доступа к вашим счетам.

## ✨ Ключевые возможности

- **Поддержка 7 банков:** Ozon, Т-Банк, Альфа-Банк, Сбербанк, Яндекс Банк, ВТБ, ВБ Банк (Wildberries).
- **Умный поиск:** по MCC-коду, по текстовому названию категории (с учетом синонимов банков) или по названию магазина (база из 400+ популярных ритейлеров).
- **Динамические категории:** Бот показывает локальные названия категорий для каждого банка (например, «Продукты» для Сбера и «Супермаркеты» для Озон).
- **Категория "Все покупки":** Учет базового кэшбэка на любые траты, за исключением MCC-кодов из черного списка банка.
- **Управление состоянием (FSM):** Сохранение состояния диалога в БД, чтобы пользователь не терял прогресс при перезапуске сервера.
- **Нативные платежи:** Интеграция Telegram Payments (ЮKassa) для поддержки проекта донатами.
- **Чистый UI:** Навигация только через Inline-кнопки с редактированием сообщений на месте (`EditMessageText`), без спама новыми сообщениями.

## 🛠 Технологический стек

- **Язык:** Java 21 (LTS)
- **Фреймворк:** Spring Boot 4.1.2 (Web, Data JPA, Validation)
- **База данных:** PostgreSQL 16
- **Миграции БД:** Flyway
- **ORM:** Hibernate 7
- **Telegram API:** `telegrambots` (Long Polling)
- **Контейнеризация:** Docker, Docker Compose
- **Сборка:** Maven
- **Тестирование:** JUnit 6, Mockito

## 🏗 Архитектура

Проект представляет собой классический монолит с четким разделением слоев:
- `bot` — слой Telegram (хендлеры, клавиатуры, роутинг обновлений).
- `service` — бизнес-логика (поиск карт, сохранение выборов, работа с платежами).
- `repository` — слой доступа к данным (Spring Data JPA).
- `domain` — JPA-сущности.
- `dto` — объекты передачи данных (records).

**Особенности БД:**
- Нормализованная схема.
- Использование `JSONB` для хранения состояния FSM (`user_state`).
- Таблица синонимов (`category_alias`), чтобы поиск понимал разговорные названия.
- Сброс настроек пользователя в начале нового календарного месяца.
