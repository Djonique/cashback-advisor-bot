# DOMAIN.md — бизнес-правила

## 1. Пользователи
- Идентификация по `telegram_chat_id` (BIGINT).
- При первом контакте создаётся `app_user` (метод `UserService.findOrCreate`).
- Состояние диалога хранится в `user_state.context` (JSONB), а не в памяти.

## 2. Месячный цикл
- Всегда используем `YearMonth.now(ZoneId.of("Europe/Moscow")).toString()` → "YYYY-MM".
- Сброс — ЛЕНИВЫЙ: при чтении всегда фильтр по текущему `year_month`.
- Старые записи не удаляются из БД, просто не возвращаются в интерфейс.

## 3. Категории и проценты
- **ЛИМИТА НЕТ.** Пользователь сам решает, сколько категорий выбрать.
- **Проценты вводит ПОЛЬЗОВАТЕЛЬ.** В базе нет «процентов банка», только `cashback_percent` в `user_bank_selection`.
- Валидация: `0 < percent <= 100`. Принимаем запятую как разделитель (5,5 → 5.5).
- Если пользователь нажал «Готово» с пустым выбором — это ОЧИСТКА выборов для этого банка за текущий месяц.

## 4. Справочник MCC
- Выгружается из PDF и грузится ОДИН РАЗ через Flyway (V2__seed_*.sql).
- Таблицы: `bank`, `category`, `bank_category`, `bank_category_mcc`, `bank_excluded_mcc`.
- `mcc_code` — всегда строка из 4 символов (с ведущими нулями).
- Обновление справочника — только новой миграцией.

## 5. Рекомендация карты
1. Читаем выборы пользователя за текущий месяц.
2. Если введены 4 цифры — ищем MCC в `bank_category_mcc`. Если текстом — ищем по `category.name`.
3. Проверяем `bank_excluded_mcc` (если MCC исключён для банка — пропускаем карту).
4. Сортируем по убыванию `cashback_percent`. Отдаём список.
